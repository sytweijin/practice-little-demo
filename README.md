# 在场 — AI 记忆工坊

> AI 接管"记"的负担，把你还给当下。

一款 AI 驱动的个人记忆留存工具。在信息过载的日常场景中（逛展、参访、开会、上课、旅行），用户随手拍下的照片、录下的语音、敲下的文字，都可以导入工具。AI 自动判断哪些值得长期保存，以"记忆卡片"的形式归档，形成可回溯的个人记忆库。

**主题六：AI + 智能认知** — 用创意形式表达对人和 AI 关系的思考。



## 产品报告

### 一、主题解读：AI + 智能认知

#### 1.1 选题背景

本次AI创作工坊的主题六为"AI + 智能认知"，要求"用创意形式表达对人与AI关系的思考"。这一命题的核心不在于展示AI技术的先进性，而在于通过具体的产品或交互形式，呈现创作者对「人应该如何与AI共生」这一根本问题的理解。

我们的答案是：**AI的最佳角色不是替代人的认知，而是接管认知的"苦力活"，让人重新专注于认知中最独特的部分——感受、判断与在场。**

#### 1.2 核心洞察：记录的悖论

在沪杭实践密集的参访行程中，我们观察到一个普遍但鲜被审视的现象：你举起手机录下讲解时，眼睛就不再看展品；你忙着记PPT时，耳朵就不在听内容。**用于"记住"的工具，恰恰在摧毁你的在场感。**

我们将这种现象称为**「记录的悖论」**——记录行为本身与体验行为之间存在根本性的张力：

- **注意力转移**：人在拍照/录像的瞬间，注意力从"理解"切换到"操作"，大脑处理模式从深度加工转为浅层存档
- **虚假的安全感**：拍下照片会产生"我已经记住了"的错觉（谷歌效应/数字健忘症），实际上照片只是存储而非记忆
- **归档即遗忘**：大量未整理的数字碎片被快速遗忘，多数素材的半衰期不超过72小时

这个悖论的核心在于：**在信息采集极度便利的时代，真正的瓶颈不是存储容量，而是意义构建的能力。**

#### 1.3 人与AI关系的三层思考

**第一层：记忆的非人化风险**

当AI可以帮人"记住一切"时，一个微妙但危险的变化会发生——记忆从"我经历过的"变成了"AI为我存储的"。人的记忆从来不是数据库，而是经过筛选、重构、赋予意义的过程。如果AI替我们完成这一步，我们实际上失去的是「将经历转化为自我认知」的能力。这就像一个读书笔记由AI代写的人——如果他从不自己写笔记，那他读过的书从未真正成为他的一部分。

**第二层：认知卸载的合理边界**

认知科学告诉我们：人类的工作记忆容量仅为4±1个组块。这意味着在信息过载场景中，AI的价值在于接管那些"值得记录但不必即时编码"的信息——类似于一个外脑，但它不替代人的理解，只降低人的认知负荷。

关键区分在于：
- **AI做筛选**（判断哪些值得留存，人可以提供方向）
- **AI做提炼**（生成结构化摘要，人可以编辑修正）
- **AI做提醒**（在遗忘临界点触发回忆，人必须亲自提取）

这三件事都是「辅助」而非「替代」。最终的认知行为——理解、联结、判断——必须由人完成。

**第三层：在场的技术哲学**

"在场"这个命名本身代表了我们对AI角色的定位。它暗示着一种新的技术伦理：**好的技术应该是隐身的。** 当"在场"工作时，用户不必打开一个界面去操作它；它应该像影子一样安静地运行，在需要时出现，在不必要时消失。

这与海德格尔的"上手状态"（Zuhandenheit）相呼应——工具真正发挥作用的时候，恰恰是它不被注意的时候。AI的终极成功不是让人惊叹"AI好厉害"，而是让人忘记AI的存在，专注于事情本身。

### 二、产品概述

**产品名称**：在场 — AI 记忆工坊

**产品定位**：一款AI驱动的个人记忆留存工具，面向信息过载场景下的参访者/学习者/旅行者群体。

**核心理念**：人负责在场，AI负责记住。

**目标场景**：企业参访、博物馆展览、会议讨论、课程讲座、旅行见闻——任何大量信息输入、易遗忘、需要后续回顾的场景。

**交付形式**：交互式网页（单页应用），后端FastAPI + 前端原生JS，零框架依赖。

**核心功能一览**：
- 采集提炼：手机拍照/录像/录音、电脑上传，断网暂存、联网自动同步
- 记忆库：卡片筛选、文件夹、批量管理、到期复习高亮
- 认知账单：AI 实际处理时长、复习投入时长、回忆完成率与场景分布
- 回忆挑战：间隔重复算法 + 到期浏览器通知 + 先默写再揭晓
- 多档案：一台电脑多人独立记忆库，JSON 导出/导入备份
- 记忆星图：场景化分星团的 3D 记忆空间，拖拽旋转、滚轮缩放、搜索高亮、点击星点查看详情
- PWA：可安装到桌面/主屏幕，离线可打开

### 三、核心主张：为什么不是"拍了就记住了"

设计这个产品时，我们反复追问自己：市面上有那么多笔记应用、摄影工具、记录软件，为什么还需要"在场"？

答案在于：**现有的工具都默认一个假设——"用户知道什么值得记录"。**

但现实是：
- 博物馆里你没有时间判断哪件展品值得细看
- 参访现场你无法预知哪个细节会在事后变得重要
- 一天的行程结束后，大量碎片已经失去了上下文

"在场"的不同之处在于：

1. **它不要求你在现场做判断**——你只需要采集，筛选由AI在事后完成
2. **它不只是存储，它帮你提炼**——从照片/录音/文字中提取核心洞察，而非原始数据堆砌
3. **它不只是存档，它帮你记住**——通过间隔重复的回忆挑战，真正巩固长期记忆
4. **它尊重个人视角**——每张卡片包含"个人归因"字段，记录"为什么这件事对我重要"，这是AI无法替代的部分

**产品形态的三大设计原则：**
- **最小化采集负担**：上传无需分类，AI自动识别素材类型和价值
- **最大化信息密度**：每张卡片只保留真正值得长期留存的内容
- **尊重认知规律**：基于遗忘曲线的回忆调度，在适当的时间触发适当的复习

### 五、功能详解

#### 5.1 场景引擎

系统设计了6种场景模板，每种场景驱动不同的AI提示词和交互行为：

| 场景 | 焦点提示词 | 素材处理速度 |
|------|-----------|------------|
| 博物馆/展览 | 聚焦展品的名称、年代、材质、历史背景 | 3分钟/素材 |
| 企业参访 | 提取核心业务、技术亮点、竞争壁垒 | 8分钟/素材 |
| 会议/讨论 | 记录议题、关键决议、行动项 | 6分钟/素材 |
| 课程/讲座 | 识别核心知识点、易错点、知识联系 | 5分钟/素材 |
| 旅行/行走 | 捕捉地点、人物、具体细节、当下感受 | 2分钟/素材 |
| 自定义 | 用户自行判断，AI按通用标准筛选 | 4分钟/素材 |

每种场景有不同的处理速度和记忆价值权重。例如企业参访的素材处理速度（8分钟/素材）高于博物馆（3分钟/素材），因为前者通常包含更密集的技术信息需要消化。

#### 5.2 筛选与提炼流程

AI分析素材时遵循一个三阶段筛选流水线：

```
素材输入 → 阶段一：信息密度评估 → 阶段二：独特性判断 → 阶段三：长期价值预测 → 保留/舍弃
```

- **信息密度评估**：素材是否包含可提取的具体事实、数据、观点
- **独特性判断**：该信息是否与已有知识重复，是否具有不可替代的视角
- **长期价值预测**：半年后回头看，这条信息是否仍然有用或有意义

这一流程的哲学前提是：**不是所有信息都值得被记住。好的记忆系统说"不"的次数比说"好"的次数多得多。**

#### 5.3 间隔重复回忆算法

回忆挑战的核心算法基于艾宾浩斯遗忘曲线，采用5级间隔递增策略：

| 级别 | 间隔天数 | 触发条件 | 记忆保留率 |
|------|---------|---------|-----------|
| 0 | 1天 | 新卡片/困难回忆后 | ~35% |
| 1 | 3天 | 中等回忆难度 | ~50% |
| 2 | 7天 | 简单回忆后 | ~65% |
| 3 | 14天 | 连续简单 | ~75% |
| 4 | 30天 | 稳定记忆 | ~85%+ |

**难度反馈机制**：每次回忆后用户选择"简单/中等/困难"，系统据此动态调整间隔：
- 简单 → 间隔提升2级（卡片被良好编码，进入长周期复习）
- 中等 → 间隔提升1级（卡片基本掌握，适度拉长）
- 困难 → 间隔降低1级（卡片尚未巩固，缩短复习周期）

这一算法的设计理念是：**记忆不是一次性写入，而是通过反复提取逐步固化的过程。** 每个回忆行为本身就在强化神经通路——这就是"测试效应"（testing effect）的实践应用。

### 六、主题深化：关于人与AI关系的再思考

#### 6.1 AI是记忆的管家，不是记忆的主人

本项目最重要的设计选择是：**AI不拥有用户的记忆。**

具体体现在：

1. **AI只做筛选，不做决定**——最终保存哪些卡片，用户确认后方可入库
2. **AI生成提要和标签，但个人归因必须由用户补充**——"这件事为什么对我重要"是AI无法回答的问题
3. **回忆挑战中，AI只是触发者，提取行为必须由人亲自完成**——AI不会替用户"想起来"

这三条原则共同构成了一个边界：**AI管理的是记忆的"容器"，而不是记忆的"内容"。**

#### 6.2 从"替代"到"协作"：认知分工的新范式

传统的人机交互模型分为两类：**自动化**（机器替代人）和**工具化**（人完全控制机器）。"在场"探索的是第三条路——**认知协作**：

| 维度 | 自动化范式 | 工具化范式 | 认知协作范式 |
|------|-----------|-----------|------------|
| AI角色 | 替代者 | 被动的工具 | 协作者 |
| 人的角色 | 旁观者 | 完全操控者 | 决策者+体验者 |
| 决策权 | AI | 人 | 共享（AI提案，人决策） |
| 认知劳动 | AI全部承担 | 人全部承担 | 分工：AI做筛选提炼，人做判断联结 |
| 风险 | 人失去能力 | 人过度疲劳 | 人在能力提升中获得解放 |

"在场"的卡片生成流程就是认知协作的典型案例：AI分析素材后提出卡片提案（包含标题、总结、标签），用户在预览后决定确认/编辑/跳过。这既不是AI独断，也不是用户从零开始——双方各司其职。

#### 6.3 从沪杭实践中生长出来的产品

需要特别指出的是，这个项目的种子数据全部来自沪杭实践的真实参访记录：

- AMD上海AI Lab（7/15）— 开源GPU生态的另一种可能
- 商汤科技（7/16）— 计算机视觉从研究到产业化的路径
- 阿里云云谷中心（7/22）— 通义千问+飞天的全栈AI布局
- 强脑科技BrainCo（7/23）— 脑机接口的科技向善实践
- 浙江大学（7/24）— 产学研协同的桥梁作用
- 浙江非遗馆（7/26）— 传统手工艺中的"慢数据"
- 浙江文学馆（7/26）— 文字作为记忆的另一种形式

**这种自指性——项目的参与者使用项目本身来管理自己的参访记忆——使得"在场"不只是一种产品假设，而是一个正在被实践的认知实验。** 当用户把今天在非遗馆看到的龙窑青瓷导入"在场"并生成卡片时，他同时在使用产品、验证产品、思考人与AI的关系——这正是主题六想要的状态。

### 七、设计决策与取舍

#### 7.1 为何不采用客户端渲染框架？

选择原生JS而非React/Vue，基于以下考虑：
- 演示场景要求零配置即可运行，无需构建工具链
- 单页应用的交互复杂度有限，原生JS完全可控
- 减少了依赖项和版本兼容性问题

#### 7.2 为何选择SQLite而非PostgreSQL/MySQL？

- 演示场景单机运行，无需数据库服务
- 零配置：首次启动自动创建数据库文件和表结构
- 文件级备份和迁移，管理成本极低

#### 7.3 为何设计预生成回退模式？

- 确保无API Key时也能演示完整交互流程
- 避免演示现场AI调用失败的风险
- 保护种子数据的质量可控性

#### 7.4 为何回忆挑战默认关闭？

基于对用户自主权的尊重：不是每张卡片都需要进入间隔重复系统。用户只有在真正想记住某条内容时才开启回忆，这确保了复习行为本身的动机质量。

### 八、局限与未来展望

#### 8.1 当前局限

- **多模态理解深度有限**：预生成模式下仅基于素材类型和场景模板生成卡片，配置 API Key 后才有真实内容理解
- **同步仍是手动边界**：多档案为本地优先，跨设备同步依赖 JSON 导出/导入或自行同步 data 目录，尚未接入云端账号
- **音频转写（配置式）**：无 API Key 时录音作为素材随卡片归档；配置 DashScope 或 OpenAI Key 后自动转写，转写文本参与卡片筛选与总结生成
- **回忆挑战的验证机制薄弱**：当前依赖用户自评难度并记录投入时长，尚未引入客观验证手段

#### 8.2 可能的演进方向

- **引入第二大脑式的自动抓取**：通过浏览器插件/手机后台自动采集用户浏览的内容
- **社交记忆共享**：同一场参访的多位参与者可以共享和对比各自的记忆卡片
- **知识图谱深化**：当前已支持卡片-标签图谱可视化，可进一步增加跨卡片相似度推荐与自动联想
- **多模态回忆**：在回忆挑战中显示原始照片/录音作为线索，增强提取效果

### 九、结语

"在场"这个项目从沪杭实践的一次日常困惑出发——"拍了这么多，我真的记住了吗"——最终走向了对人与AI关系的深入探讨。

它的答案是温和但坚定的：**AI应该帮助人更好地成为人，而不是替代人。** 当AI接管了"记"的负担，人才有可能真正专注于"在场"——专注于感受、判断、联结这些AI无法替代的人类特质。

这或许就是主题六想让我们体会的东西：**AI与人的关系，不是谁取代谁的问题，而是如何通过合理的分工协作，让双方都成为更好的自己。**

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. （可选）配置 API Key
cp .env.example .env
# 编辑 .env 填入 DASHSCOPE_API_KEY（留空则使用预生成模式）

# 3. 启动（首次启动会自动生成 HTTPS 证书，手机端也能现场录音）
python main.py

# 4. 打开浏览器
# 电脑访问 https://127.0.0.1:8001
# 手机访问启动时打印的 https://<电脑局域网IP>:8001（同一 WiFi，首次需点“高级→继续访问”）
```

> 手机端建议用 Chrome / Edge 打开后「添加到主屏幕」；桌面浏览器出现「安装应用」按钮时可直接安装为应用。
> 断网时采集会自动暂存在浏览器本地，恢复网络后点击提示条「立即同步」即可自动导入。

## 核心功能

### 1. 采集提炼
- 选择场景类型（博物馆 / 企业参访 / 会议 / 上课 / 旅行 / 自定义）
- 手机端支持拍照、录像、录音；电脑端支持拖拽上传与浏览器摄像头/录音
- 断网时采集自动暂存，恢复网络后一键同步
- 填写个性化方向（可选）：告诉 AI 你想重点记住什么
- AI 自动筛选值得留存的内容，生成记忆卡片（客观总结 + 个人归因 + 标签）

### 2. 记忆库
- 所有卡片按时间倒序排列
- 按场景类型筛选
- 到期复习卡片高亮「待复习」标记
- 点击卡片查看详情、相关记忆、编辑、删除

### 3. 认知账单
- 记忆卡片总数
- AI 实际处理时长（按会话真实计时）
- 复习投入时长与平均难度
- 已处理素材数、回忆完成率
- 估算节省时间（按场景系数，仅作对照）
- 按场景分布可视化

### 4. 回忆挑战
- 基于间隔重复算法（遗忘曲线：1天 / 3天 / 7天 / 14天 / 30天）
- 默认关闭，由用户自行决定哪些卡片值得进入复习
- 到期自动提醒（浏览器通知，需用户授权）
- 先默写再揭晓答案，并记录每次回忆投入时长

### 5. 多档案
- 同一台电脑可为多人创建独立档案，卡片与账单互不干扰
- 切换档案自动加载对应数据；导出 JSON 可备份或在其他设备导入

### 6. 记忆星图
- 基于 Three.js 的 3D 记忆空间，每种场景（企业参访、展览、会议等）自动形成一个星团
- 卡片是星团中的发光星点，共享标签的卡片之间用金色光线连接，悬停可查看标签名
- 支持拖拽旋转、滚轮缩放、点击星点查看详情、关键词搜索高亮过滤
- 深空背景下三层恒星、星云与雾化景深，加载失败时自动回退到 2D 图谱

### 7. PWA 安装与离线
- 支持安装到桌面/主屏幕，浏览器打开即可使用
- 静态资源离线缓存，断网时仍可打开应用并暂存采集

## 技术架构

```
前端  HTML / CSS / 原生 JS + Service Worker（PWA，无框架依赖）
  ↕  HTTP / Fetch（请求头/ Cookie 携带档案标识）
后端  Python FastAPI
  ├── 素材上传与分类（含断网采集暂存队列）
  ├── 通义千问 Vision / OpenAI GPT-4V 多模态分析（真实计时）
  ├── 记忆卡片 CRUD 与多档案隔离（data/memory_*.db）
  ├── 间隔重复回忆调度（到期提醒 + 回忆计时）
  ├── 记忆星图（3D 星空，Three.js）
  └── 认知账单统计（真实时间 + 估算对照）
  ↕
存储  SQLite（零配置，默认 data/memory.db，多档案为 data/memory_<档案名>.db）
```

## 配置 API Key（可选）

不配置也能完整演示（使用预生成模式）。配置后可获得真实的 AI 图片理解和文本提炼能力。

### 通义千问 Vision
1. 访问 https://dashscope.console.aliyun.com/ 申请 API Key
2. 填入 `.env` 文件：`DASHSCOPE_API_KEY=sk-...`

### OpenAI 兼容接口
```
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=https://api.openai.com/v1
```

## 替换真实素材

### 替换照片
将真实参访照片放入 `static/uploads/` 目录，然后在记忆库中编辑对应卡片的图片路径。

### 替换种子数据
编辑 `seed.py` 中的 `SEED_CARDS` 列表，修改标题、摘要、个人归因等内容。删除 `data/memory.db` 后重启即可重新生成（多档案的数据库为 `data/memory_<档案名>.db`）。
