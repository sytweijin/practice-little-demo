# 在场 — AI 记忆工坊

> AI 接管"记"的负担，把人还给当下。

一款 AI 驱动的个人记忆留存工具。在信息过载的日常场景中（逛展、参访、开会、上课、旅行），随手拍下的照片、录下的语音、敲下的文字，都可以导入工具。AI 自动判断哪些值得长期保存，以"记忆卡片"的形式归档，形成可回溯的个人记忆库。

**主题六：AI + 智能认知** — 用创意形式表达对人与 AI 关系的思考。

## 产品报告

### 一、记录的悖论

在沪杭实践密集的参访行程中，一个普遍但鲜被审视的现象反复出现：举起手机录下讲解时，眼睛就不再看展品；忙着记 PPT 时，耳朵就不在听内容。**用于"记住"的工具，恰恰在摧毁在场感。**

将这种现象称为**「记录的悖论」**——记录行为本身与体验行为之间存在根本性的张力：

- **注意力转移**：拍照/录像的瞬间，注意力从"理解"切换到"操作"，大脑处理模式从深度加工转为浅层存档
- **虚假的安全感**：拍下照片会产生"已经记住了"的错觉（谷歌效应），实际上照片只是存储而非记忆
- **归档即遗忘**：大量未整理的数字碎片被快速遗忘，多数素材的半衰期不超过 72 小时

核心瓶颈不在存储容量，而在**意义构建的能力**。采集极度便利的时代，真正稀缺的是"判断什么值得记住、以及把它变成自己的"这个过程。

### 二、核心理念：人负责在场，AI 负责记住

AI 的最佳角色不是替代人的认知，而是接管认知中的"苦力活"，让人重新专注于感受、判断与在场。

这一立场基于三重考量：

1. **记忆的非人化风险**。当 AI 帮人"记住一切"时，记忆从"经历过的"变成了"AI 替存储的"。人的记忆从来不是数据库，而是经过筛选、重构、赋予意义的过程。如果这一步被 AI 包办，失去的正是将经历转化为自我认知的能力。

2. **认知卸载的合理边界**。人类工作记忆容量仅 4±1 个组块。AI 的价值在于接管那些"值得记录但不必即时编码"的信息——做筛选、做提炼、做提醒——但理解、联结、判断这些核心认知行为必须由人完成。

3. **工具的"上手状态"**。好的技术应该是隐身的。"在场"工作时，用户不必频繁操作它；它安静地运行，在需要时出现。这与海德格尔的"上手状态"（Zuhandenheit）相通——工具真正发挥作用的时候，恰恰是它不被注意的时候。

**核心边界：AI 管理记忆的"容器"，而不是记忆的"内容"。** 具体体现为：AI 提出卡片提案但用户确认后方可入库；AI 生成提要和标签但"个人归因"由用户亲自填写；回忆挑战中 AI 只负责在遗忘临界点触发，提取行为必须由人亲自完成。

### 三、产品概述

|  |  |
|--|--|
| **定位** | AI 驱动的个人记忆留存工具，面向信息过载场景下的参访者 / 学习者 / 旅行者 |
| **场景** | 企业参访、博物馆展览、会议讨论、课程讲座、旅行见闻 |
| **交付形式** | 交互式单页应用（FastAPI + 原生 JS，零框架依赖） |

**核心功能：**

- **采集提炼**：拍照 / 录像 / 录音 / 文字，断网暂存、联网自动同步；快速与深度两种模式
- **记忆库**：卡片筛选、文件夹、批量管理、到期复习高亮、全文搜索
- **认知账单**：AI 实际处理时长、复习投入时长、回忆完成率、场景分布
- **回忆挑战**：间隔重复算法（遗忘曲线 1→3→7→14→30 天）、到期通知、先默写再揭晓
- **记忆星图**：3D 记忆空间 + AI 跨场景联结发现（增量保存、可锁定）+ 月度叙事回顾
- **多档案与同步**：多人独立记忆库，全量快照导出 / 智能同步导入（回忆进度保真）
- **PWA**：可安装到桌面 / 主屏幕，离线可打开，支持接收系统分享

### 四、与现有工具的本质区别

市面上有大量笔记应用和记录软件，但它们都默认一个假设——**用户知道什么值得记录**。现实是：博物馆里没有时间判断哪件展品值得细看，参访现场无法预知哪个细节日后会变得重要，一天结束后大量碎片已经失去了上下文。

"在场"的不同之处：

1. **不在现场做判断** — 只管采集，筛选由 AI 在事后完成
2. **不止存储，更做提炼** — 从素材中提取核心洞察，而非原始数据堆砌
3. **不止存档，更做巩固** — 通过间隔重复的回忆挑战，真正巩固长期记忆
4. **尊重个人视角** — 每张卡片的"个人归因"字段记录"为什么这件事对我重要"，这是 AI 无法替代的部分

**设计原则：** 最小化采集负担（上传无需分类）；最大化信息密度（每张卡片只保留真正值得长期留存的内容）；尊重认知规律（基于遗忘曲线调度复习时机）。

### 技术选型

| 层级 | 选型 | 理由 |
|------|------|------|
| 前端 | 原生 HTML/CSS/JS | 零依赖部署，无构建工具链 |
| 后端 | Python FastAPI | 异步支持好，自动生成 API 文档 |
| 存储 | SQLite | 零配置，单文件，文件级备份 |
| AI 推理 | 通义千问 VL / OpenAI VL | 多模态理解，覆盖图片+文字+语音转写 |
| 3D 渲染 | Three.js（CDN import） | 星空记忆图谱 |

### 数据模型

**cards 表（记忆卡片）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| scene_type | TEXT | 场景（museum / enterprise / meeting / class / travel / custom） |
| title | TEXT | 卡片标题 |
| summary | TEXT | 客观总结 |
| personal | TEXT | 个人归因（用户填写） |
| source_kind | TEXT | 素材类型（image / audio / text） |
| image_url | TEXT | 关联图片路径 |
| tags | TEXT(JSON) | 标签列表 |
| source_date | TEXT | 来源日期 |
| status | TEXT | 状态（draft / confirmed / deleted） |
| recall_enabled | INTEGER | 是否开启回忆 |
| next_recall | TEXT | 下次回忆日期 |
| recall_interval | INTEGER | 当前间隔级别（0-4） |
| difficulty | INTEGER | 最近回忆难度 |
| recall_seconds | INTEGER | 累计回忆投入秒数 |
| batch_id | TEXT | 批次 / 文件夹标识 |
| created_at | TEXT | 创建时间 |

**ledger 表（认知账单）：** 记录每次会话的素材数、AI 实际处理秒数、复习投入秒数、生成卡片数。

**ai_connections 表：** AI 发现的跨场景联结（card_a, card_b, reason, locked）。

**narratives 表：** AI 生成的月度叙事回顾（title, body, date_start, date_end）。

### 场景引擎

6 种场景模板驱动不同的 AI 提示词和记忆价值权重：

| 场景 | 焦点 | 估算速度 |
|------|------|---------|
| 博物馆 / 展览 | 名称、年代、材质、历史背景 | 3 分钟/素材 |
| 企业参访 | 核心业务、技术亮点、竞争壁垒 | 8 分钟/素材 |
| 会议 / 讨论 | 议题、关键决议、行动项 | 6 分钟/素材 |
| 课程 / 讲座 | 核心知识点、易错点、知识联系 | 5 分钟/素材 |
| 旅行 / 行走 | 地点、人物、具体细节、当下感受 | 2 分钟/素材 |
| 自定义 | 通用标准筛选 | 4 分钟/素材 |

### 间隔重复算法

基于艾宾浩斯遗忘曲线，5 级间隔递增：

| 级别 | 间隔 | 触发条件 | 保留率 |
|------|------|---------|--------|
| 0 | 1 天 | 新卡片 / 困难后 | ~35% |
| 1 | 3 天 | 中等难度 | ~50% |
| 2 | 7 天 | 简单回忆后 | ~65% |
| 3 | 14 天 | 连续简单 | ~75% |
| 4 | 30 天 | 稳定记忆 | ~85%+ |

用户自评难度后动态调整：简单 +2 级，中等 +1 级，困难 -1 级。每个回忆行为本身就在强化神经通路——"测试效应"（testing effect）的实践。

## 认知协作范式

传统人机交互分两类：**自动化**（机器替代人）和**工具化**（人完全控制机器）。"在场"探索第三条路——**认知协作**：

| 维度 | 自动化 | 工具化 | 认知协作 |
|------|--------|--------|---------|
| AI 角色 | 替代者 | 被动工具 | 协作者 |
| 人的角色 | 旁观者 | 完全操控 | 决策者 + 体验者 |
| 决策权 | AI | 人 | 共享（AI 提案，人决策） |
| 认知劳动 | AI 全担 | 人全担 | 分工：AI 筛选提炼，人判断联结 |

卡片生成流程就是典型案例：AI 分析素材后提出卡片提案（标题、总结、标签），用户预览后决定确认 / 编辑 / 跳过。既非 AI 独断，也非用户从零开始。

种子数据全部来自沪杭实践的真实参访记录（AMD、商汤、阿里云、强脑科技、浙大、浙江非遗馆、浙江文学馆）。这种自指性——使用项目本身来管理参访记忆——使其不只是一个产品假设，而是一个正在被实践的认知实验。

## 局限与演进

**当前局限：**

- 跨设备同步依赖手动导出 / 导入，尚未接入云端账号
- 回忆难度和投入时长依赖用户自评
- AI 联结发现和叙事回顾需要配置 API Key，无 Key 时标注为占位

**演进方向：**

- 云端账号自动同步
- 本地 ASR 兜底（浏览器 Web Speech API）
- 图片 OCR（提取 PPT 截图、展板中的文字）
- 社交记忆共享（同一场参访的多人对比）

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2.（可选）配置 API Key
cp .env.example .env
# 编辑 .env 填入 DASHSCOPE_API_KEY（留空则使用预生成模式）

# 3. 启动（首次自动生成 HTTPS 证书，手机端也能录音）
python main.py

# 4. 打开浏览器
# 电脑访问 https://127.0.0.1:8001
# 手机访问启动时打印的 https://<局域网IP>:8001
```

> 手机端建议用 Chrome / Edge 打开后「添加到主屏幕」。

## 配置 API Key（可选）

不配置也能完整体验（预生成模式）。配置后获得真实 AI 多模态理解能力。

**通义千问（推荐）：** 访问 https://dashscope.console.aliyun.com/ 申请 Key，填入 `.env`：

```
DASHSCOPE_API_KEY=sk-...
DASHSCOPE_TEXT_MODEL=qwen-plus      # 可选，默认 qwen-plus
```

**OpenAI 兼容接口：**

```
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_VISION_MODEL=gpt-4o          # 可选
OPENAI_TEXT_MODEL=gpt-4o-mini       # 可选
```
